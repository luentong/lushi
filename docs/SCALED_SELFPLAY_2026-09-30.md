# 多卡组 PPO 扩量：32,768 局固定预算

本轮目标是验证持续增加新自博弈经验能否改善强度。训练从
`reports/entity-pilot128-v2-repaired/entity-ppo.pt` 初始化，保留 256 维、6 层、
8 头的实体模型作为扩量基线；没有把架构扩容、记忆模块或留牌策略训练混入本次实验。
旧模型不因新任务启动而被替换。

## 固定配置

- 训练机：FusionOne 内网 910B3；隔离目录 `/workspace/hs_observer_entity_20260929`。连接信息不写入公开仓库。
- 32 轮 × 1024 局 = 32,768 局新对局，每轮重新采样；每轮 2 个 PPO epoch。
- 八套牌：龙战、光铸骑、龙猎、穆格萨、任务牧、先驱术、虚灵瞎、兆示贼；
  使用 `config/decks_20260925_smoke8.json` 中固定变体，不代表全部 127 套牌已训练。
- 每轮完整覆盖八套牌的有序配对和 learner 两个座位，每个组合重复 8 次。
- 学习率 `1e-5`，训练 batch 32，终局优势，保留已有整局等权方式。
- 最多 8 个历史对手：固定初始化锚点 + 最近 7 个版本。历史对手每套 learner 卡组独立轮换。
- 16 个 CPU 游戏进程，共享 NPU 2 上的驻留模型和批量推理，推理 batch 上限 32。
- NPU 3 执行固定开发/确认评测；训练和评测阶段在协调器内顺序执行。
- 每局动作上限 400。失败写报告，原配对槽位最多换新 seed 重试两次；未终局不标平局。
- 首次种子 `202703010000`；开发 `202801010000`；确认 `202901010000`。这些是随机种子，非日期。

## 采样正确性与吞吐

新增 `scripts/entity_parallel_rollout.py`：游戏子进程只维护 CPU 模拟状态和可见观察，
主进程按 learner / 历史策略分组合批推理。策略在一轮采样期间冻结；模型更新后才开始新一轮。
每局使用独立动作采样 RNG，固定计划槽位、卡组、座位、对手版本和完整 action trace。
不同对手版本按组排队，减少历史池扩大后的小推理 batch；最终训练数据按槽位排序。

实际动作仍按策略概率采样。改变 worker 数时真实浮点模型可能因 batch 数值差异改变极少数
采样结果，不能承诺逐位完全相同；确定性测试策略已验证单 worker 和双 worker 轨迹一致。
行为概率、最终回报、源/目标动作及 trace_step 保存在轨迹中，支持重放和 PPO 对账。

## 恢复与评测

`scripts/run_entity_scale.py` 按轮启动独立进程，保存优化器、checkpoint、压缩轨迹、
SHA256 和日志。下一轮加载上轮权重和优化器；锚点不变。`--resume` 会验证配置、源码和
输入 hash，跳过已完成轮次，失败轮次使用新 attempt 文件名，保留失败产物。
进程锁避免同一目录被两个协调器重复训练。恢复粒度为完整训练轮，不是单个环境步骤。

每 8 轮做一次开发评测：8×8 有序 matchup × 2 seed × 2 模型座位 = 256 局。
初始化自对战基线用相同任务、规则和 seed 对照。全部 32 轮结束后按开发集净增选候选，
再进行独立确认：8×8×8×2 = 1024 局，初始化基线另跑 1024 局。
开发集分数低不会提前取消训练预算；失败、源码漂移或不完整回合会停止并留下错误。
确认结果、逐卡组净增和价值校准供人工审查，不自动部署或宣称职业水平。

## 启动/恢复

在隔离目录、确认设备空闲后执行：

```bash
. /usr/local/Ascend/cann-8.5.0/set_env.sh
/usr/local/python3.11.14/bin/python3.11 -u scripts/run_entity_scale.py \
  --init-checkpoint reports/entity-pilot128-v2-repaired/entity-ppo.pt \
  --deck-config config/decks_20260925_smoke8.json \
  --output-dir reports/entity-scale32768-20260930 \
  --device npu:2 --eval-device npu:3
```

恢复使用同一命令追加 `--resume`。状态文件为输出目录的 `pipeline.json`；
当前进程、日志、已完成局数、每轮采样耗时及平均推理 batch 都可追踪。

## 已完成的小规模验证

- 32 局 NPU 并行采样/更新烟测：两轮全部终局，0 失败。
- 协调器两轮 32 局烟测：恢复后仍只有两个 attempt，不重复训练；第二轮没有重置优化器，
  初始化模型和首轮模型各作为对手 8 局。
- 回归验证覆盖：奖励玩家视角、行为概率、终局/截断区分、失败重试、固定配对、轨迹可复现。

本轮后续应根据独立评测决定是否扩到更多卡组，以及是否进行 384×8 等容量对照。
首次扩量实验的运行时间需按正式首轮的采样、写盘和训练耗时估算，不能用 NPU 峰值算力推算。
