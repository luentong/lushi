# 多卡组自博弈：均衡排程与独立对照

本轮不把某个出牌顺序写成策略规则。训练主线仍是完整对局的终局收益；固定战术局面只用于独立诊断，不能替代整局强度评测。

## 第一轮：验证历史对手池轮换

`train_entity_selfplay.py` 现在在**每局**选历史对手，而不是每一训练轮只选一个版本。版本随轨迹和终局记录保存；失败重试沿用原计划槽位，不会跳过某个对手。训练目录为 910B `/workspace/hs_observer_entity_20260929`。

- 初始化：`reports/entity-pilot128-v2-repaired/entity-ppo.pt`，仅为研究候选。
- 八套牌：龙战、光铸骑、龙猎、穆格萨、任务牧、先驱术、虚灵瞎、兆示贼；具体变体见 `config/decks_20260925_smoke8.json`。
- `2 × 16 = 32` 局，全部终局，0 失败。第一轮对 bootstrap 16 局；第二轮对 bootstrap 和 round1 各 8 局。共有 1279 条 learner 决策。
- 输出：`reports/entity-multideck-ppo-20260930-v1.pt`、同名前缀的 `.report.json` 和每轮轨迹；训练约 107 秒。

与初始化模型进行不重用训练 seed 的开发集对照：八套牌全部有序配对，每配对一个 seed，并交换候选所在座位，合计 **128/128** 局有效，0 失败/截断。新模型 **64 胜、64 负**；候选先手 35/64，后手 29/64。64 对中，候选横扫 18 对、各胜一局 28 对、被横扫 18 对。配对均分的保守 95% 区间约为 **33.0%–67.0%**。这轮没有提供整体变强的证据，**不晋级、不部署**。原始开发集报告为 `reports/entity-multideck-ppo-20260930-v1-eval/evaluation.json`，本地拷贝为 `reports/entity-multideck-ppo-20260930-v1-evaluation.json`。

第一轮短排程虽包括八套牌，但每套在双方位置的次数不均。此后 `rollout_schedule` 改为循环偏移排程：当双方来自同一候选集合时，即使只完成一个短前缀，每完成 `2 × 卡组数` 局，每套牌也在双方位置各出现两次，并覆盖 learner 两种座位。完整循环仍覆盖全部有序配对与座位。新增单元测试。**此修正没有追溯改变上面的 32 局数据。**

## 第二轮：均衡完整循环

从同一个初始化模型独立启动，不从未晋级的第一轮接训。配置为八套牌、每轮 128 局（完整有序配对与 learner 座位循环）、两轮，共 256 局；NPU 2、学习率 `1e-5`、每轮 2 个 PPO epoch。输出前缀为 `reports/entity-multideck-ppo-20260930-balanced256`。256/256 局终局，0 失败；每轮的 128 种 `(我方卡组, 对方卡组, learner 座位)` 组合均不重复。第一轮采集 5251 条 learner 决策；第二轮 5364 条，分别面对 bootstrap 与 round1 各 64 局。训练报告记录了卡组、规则源码、初始化权重的 SHA-256；用时约 871 秒。

使用同一批**训练外**开发 seed (`202610310000` 起) 将两个中途 checkpoint 分别对照初始化模型；八套牌全部有序配对，每配对一个 seed、交换模型座位，共 128 局/模型：

| 模型 | 胜/负 | 有效/计划 | 被横扫 / 一胜一负 / 横扫 | 配对均分的保守 95% 区间 |
| --- | ---: | ---: | ---: | ---: |
| round1 | 75/53 | 128/128 | 16 / 21 / 27 | 41.6%–75.6% |
| round2 | 74/54 | 128/128 | 17 / 20 / 27 | 40.8%–74.8% |

两轮均为 0 失败、0 截断、0 非法动作。开发集下 round2 没有超过 round1；两轮区间均跨 50%。按候选所用卡组看，round2 的龙战为 16/16，而任务牧为 4/16、穆格萨为 6/16、兆示贼为 6/16：这是严重的分组不均迹象，尽管每组只有 16 局，不能当作真实卡组强弱结论。**两轮都不晋级、不部署，也不因总体均值高于 50% 就宣称策略已改善。**原始开发集见 `reports/entity-multideck-ppo-20260930-balanced256-round{1,2}-eval/evaluation.json`，本地有相应 `*-evaluation.json` 拷贝。

下一关应先用独立于开发集的新 seed 扩大座位配对检验，特别核对上述弱分组；若仍有系统性回退，不应仅增加 epoch 或把同一批对局继续回放。之后再扩大卡组变体和历史对手池。这里没有为 Carrier Whelp / Cannonmaster 顺序添加专门训练标签；它需要通过完整对局收益与可观察状态学习，而不是硬编码出牌顺序。

## 冻结 round1 后的独立确认

开发集只用于在 round1 / round2 中选择候选。冻结 round1 后，在另一批 seed (`202611010000` 起) 对初始化模型评测：八套牌全部有序配对，每组两个 seed、交换模型座位，合计 **256/256** 局有效，0 失败/截断/非法动作。round1 为 **131 胜、125 负（51.17%）**；128 对座位交换 seed 的保守 95% 区间约 **39.2%–63.2%**。这与开发集的 75/128（58.59%）不一致，不能宣称已实现可复现的总体强度提升。

各己方卡组在确认集的 32 局结果：龙战 27/32、虚灵瞎 25/32、龙猎 22/32、光铸骑 17/32、穆格萨 14/32、先驱术 12/32、兆示贼 10/32、任务牧 **4/32**。分组结果表明总体均值掩盖了明显回退；本轮对任务牧尤其不适合作为实战建议。原始确认报告：`reports/entity-multideck-ppo-20260930-balanced256-round1-confirm/evaluation.json`，本地拷贝：`reports/entity-multideck-ppo-20260930-balanced256-round1-confirmation.json`。

结论仍是 **不晋级、不部署、不继续盲目加 epoch**。下一步应做跨卡组族的训练分层与价值校准审计，并用强度经过验证的旧策略/历史池防止新职业训练牺牲已有能力；这些都需要再经独立对战，而不能仅凭训练 loss 或某个卡组的高胜率。最新服务器回归测试为 **879/879** 通过。

来源、卡组配置和初始化权重 SHA-256 随训练报告保存。此次只是八种各一个变体，不能推断 91/127 套卡组或真实天梯强度。

## 第三轮：按完整对局等权、按卡组轮换历史对手

上一轮的 256 局虽然每套牌各 32 局，但决策行数从 1124 到 1473 不等；旧 PPO 对每条决策等权，长局因此占更多梯度。修订后每局的所有决策权重总和相同，每套牌的对手版本也单独循环均衡。对手池始终保留初始化权重，避免容量满时将可信锚点挤出。`scripts/audit_entity_rollouts.py` 提供按游戏、卡组和对手版本的价值审计。

从原初始化权重独立开始了 3 × 256 = **768 局**、8 套牌完整有序 matchup 的实验。首轮跑完后，对手池截取边界错误阻止进入第二轮；首轮 checkpoint 和 256 局数据有效且保留。修复并新增测试后，使用 `--round-offset 1`、原 seed、恢复的优化器、原初始化锚点及首轮 checkpoint 完成剩余 512 局。三轮均全部终局、0 失败、0 KL 提前停止；每套牌累计 96 局，第二轮每套牌分别对初始化/首轮各 16 局，第三轮初始化/首轮/第二轮总体为 87/83/86 局。输出位于 910B `/workspace/hs_observer_entity_20260929/reports/entity-multideck-ppo-20260930-gamebalanced768*`，续跑输出前缀带 `-resume`。**这仍是较小的强化学习试验，不是充分训练到职业水平。**

关键评测口径修正：某卡组的原始候选胜率不能直接解释为相对旧模型的提升/回退，因为卡组本身有强弱。新增 `scripts/compare_entity_evaluations.py`，用同一组卡组配对、种子和模型座位，将候选与“初始化模型对初始化模型”的成绩相减。任务牧在开发集的原始 3/16 看似严重，但初始化自对战基线为 4/16；首轮实际仅少 1 局。不能据此声称大幅退化。

同一开发集（64 对座位交换 seed，128 局/版本）比较如下：

| 候选 | 候选得分 | 初始化自对战基线 | 净差 | 座位配对 bootstrap 95% 区间 |
| --- | ---: | ---: | ---: | ---: |
| round1 | 69/128 | 67/128 | +1.6 个百分点 | −3.9～+7.0 个百分点 |
| round2 | 71/128 | 67/128 | +3.1 个百分点 | −2.3～+8.6 个百分点 |
| round3 | 72/128 | 67/128 | +3.9 个百分点 | −2.3～+10.2 个百分点 |

第三轮按开发集总净差冻结为独立确认候选；开发集所有区间仍跨 0。评测是无搜索的贪心 entity policy，对真实 PUCT/实时建议的质量不能直接外推。

价值头独立诊断：在各模型自身行动产生的开发集局面上，round1/2/3 的每局宏平均 Brier 分别为 0.177/0.142/0.180，首个候选决策 Brier 为 0.193/0.151/0.200。round3 的纯策略胜率略高，但价值头不如 round2 校准；由于不同策略会走入不同局面，这不是严格同状态因果比较，仍足以阻止仅凭纯策略胜率部署。

独立确认使用全新 seed、每个有序 matchup 两个 seed 且交换模型座位；确认结果出来前，不再改选 round1/2。

### 冻结 round3 后的独立确认结果

使用与开发集不同的 `202612150000` 起始 seed，八套牌全部有序配对、每组两个 seed 和模型座位交换，候选与初始化自对战基线各 **256/256** 局有效；均 0 失败、0 截断、0 非法动作。结果：round3 **123/256（48.0%）**，初始化自对战基线 **128/256（50.0%）**。同作业配对后的净差 **−2.0 个百分点**，128 对座位交换 seed 的探索性配对 bootstrap 95% 区间为 **−6.6～+3.1 个百分点**。开发集的 +3.9 个百分点没有在独立确认中复现，**不晋级、不部署**。

不能把不同卡组的原始胜率直接解读成模型退化。与同卡组旧策略基线逐局对照后，任务牧在确认集为候选 6/32、基线 5/32，净增 1 局；虚灵瞎为候选 18/32、基线 24/32，净少 6 局，是需要后续核对的分组信号。每组仍只有 32 局，不能当成天梯卡组强度排名。

确认集上，候选价值头对自身到达状态的每局宏平均 Brier 为 **0.167**、首个候选决策 Brier 为 **0.203**；初始化模型自对战对应为 **0.197 / 0.255**。两策略到达状态不同，因此不能把差值当作同状态因果比较，但说明“价值估计改善”与“对战策略变强”不是同一件事。PPO 更新的平均动作熵约 1.16–1.20、最大批次近似 KL 约 0.01，未见明显策略熵崩塌或过大的单批更新；更可能的瓶颈是终局 ±1 反馈对复杂组合动作的信用分配和少量对局的方差，而非此次对手排程错误。这个解释仍是假设，需用下一轮对照验证。

本轮远程完整回归 **889/889** 通过。下一轮不应简单沿此 checkpoint 追加 epoch；应先设计能提供更明确动作优劣信号的训练目标，并在更大的冻结开发/确认集上同时检查多卡组净增和价值校准。所有本轮 checkpoint 只保留为研究工件。
