# 炉石 AI 职业级训练路线审计

日期：2026-09-29。性质：代码审计、只读诊断和研究方案；不是已实现或已达到职业水平的声明。本轮没有修改现有训练程序、停止任务或启动新训练。

## 结论

目前主要问题不是 epoch 不够，而是观察表示不完整、教师强度没有形成持续改进闭环，以及有效经验和验证覆盖不足。更宽更深的模型是合理实验，但无法补回输入中不存在的信息，也不能通过反复模仿固定教师自动获得可靠的职业级策略。

建议主线：完整的可见状态/历史与 belief → 实体关系网络 → 监督冷启动 → 持续对手池自博弈 RL → 选择性搜索重分析 → 独立对局与人类评测。保留现有引擎、数据基础设施和模型作为资产，不要求推倒重来，也不要求整个模拟器先达到零 bug。

## 1. 本次直接核实的证据

### 1.1 当前新增教师不使用最佳 checkpoint

`scripts/generate_policy_value_data.py:369` 的 `play_game()` 创建 `InformationSetMCTSPolicy` 时未传入 policy/value 模型。非神经分支在 `src/hsa/mcts.py:1081` 用启发式 rollout，然后调用 `evaluate_state()`。

`src/hsa/mcts.py:23` 的非终局估值主要由生命/护甲差、场面价值差、武器价值差、手牌数量差组成。它不是学习出来的长期胜率估计。

22021 上当前生成进程的实际参数是：2048 局新增数据，4 个隐藏状态采样 × 每样本 32 次搜索，rollout_depth=3，8 个并行任务，policy target 为 action-values softmax。manifest 确认 conditional_training.enabled=false。

因此当前主数据路径是“固定启发式搜索 → 学生拟合”，不是“学生变强 → 搜索教师变强 → 生成更好的新数据”。已有搜索代码支持神经模型，不等于当前教师入口实际使用了它。旧条件纠正样本仍会混入训练，不能把新批次未开启条件采集理解为历史完全没有条件数据。

终局 value 标签来自该行为策略的实际输赢；它估计的是这种后续打法下的结果，不是任意最优续着下的胜率。当前 action-Q 标签来自搜索估值，其语义也不能直接等同于真实获胜概率。

### 1.2 引擎保存了信息，但网络没有收到

`src/hsa/encoding.py:201` 的 schema-v6 状态编码包括血量、法力、区域卡牌计数、部分手牌/场面动态属性、受伤角色数量、地标冷却及汇总语义。

但 `Player` 中多项决策相关状态没有进入该编码，例如英雄技能 ID、灌注进度、兆示次数、魔网升级、任务状态。卡牌 ID 主要以区域直方图出现；动态身材按位置另行记录，两者没有完整逐实体绑定。地标只有耐久/冷却，不含其 ID。公开行动历史和候选卡组 belief 也没有直接编码到网络状态中。

已在 22021 用现有 Python 3.11 环境做只读输入敏感性探针：复制同一游戏对象，仅修改以下字段，再比较 `encode_state()`。结果：

| 修改字段 | 改变的状态输入维数 |
| --- | ---: |
| herald_count | 0 |
| hero_power_imbues | 0 |
| leyline_upgrade | 0 |
| hero_power_id | 0 |
| active_quests | 0 |

探针使用 expanded-executable 词表，输出 7960 维。这是对编码信息损失的测试，不是在声称这些人工改动分别组成真实可达对局，亦不是对任意一条坏打法的完整因果归因。编码代码本身也未读取这些字段。

合法动作列表或搜索后的新局面有时可以间接暴露部分差异，但这不能代替给 value/policy 提供完整观察。尤其 value head 只读状态时，相同编码必然给出相同预测。

进一步需要测试：同样受伤角色数量但不同角色已经受伤；相同区域卡牌集合但不同实体身上的附魔；相同表面身材但不同沉默/亡语/延迟触发；同样场面但不同公开出牌历史。修复重点是通用状态表示，不是为某张牌单加一个规则。

### 1.3 当前更大模型仍是残差 MLP

`src/hsa/torch_model.py:367` 的 `StructuredResidualPolicyValueNet` 用卡牌身份嵌入、区域聚合、位置标量和残差全连接网络，再与动作特征组合产生 policy/Q/value。它已有有用的卡牌语义特征，并非纯卡牌 ID 模型；但不是逐实体关系注意力，也没有历史序列编码。

`scripts/run_strategy_v3_910b.sh` 安排的 1024×8 控制组和 1536×12 大模型是同数据随机初始化的容量对照；未传 `--init-checkpoint`。它们可以回答“容量增加是否有用”，不能称为基于最佳 checkpoint 的连续强化学习。

### 1.4 当前证据不支持“已经明显变强”

`reports/decision-quality-loop-20260928/README.md` 记录：教师动作吻合率 46.75% → 47.39%，value Brier 0.1414 → 0.1388；直接对战两组分别 10/20 和 9/20。样本太小，且没有显示明确优势。

这是现有完整报告的结果，不是对正在生成的 v3 模型作提前判断。文件名中的 best 或最好的验证 epoch，只代表某个选择指标，不自动代表最强实战模型。

当前 exact-deck 留出靠分片文件名匹配；训练脚本对 base/priority 过滤，但没有同样过滤 tactical 分片。尚未证明发生了实际污染，不过不能据此声称完成了严格的卡组族和数据来源级隔离。

## 2. 研究中可以借鉴什么

### 2.1 真正打过强人类选手的炉石研究

ByteDance 的 [Mastering Strategy Card Game (Hearthstone) with Improved Techniques](https://arxiv.org/html/2303.05197v2) 使用持续深度 RL、历史策略对手池和 OSFP，不需要训练/推理时前瞻搜索。其最好非作弊训练使用 24 张 V100、5856 CPU 核，训练 23 天，并在两场 Bo5 中均以 3:0 击败一位曾达国服前十的玩家。

边界很重要：这是 2015 黑石山版本、3 职业、350+ 卡的模拟环境，不是当前完整标准；比赛样本也不足以证明对所有职业选手普遍占优。这里可借鉴的是训练闭环和工程规模，而不是照搬“23 天就能职业级”。

### 2.2 泛化模型结构有更贴近的开源参考

[GeneralizableHS / AAMAS 2025](https://ifaamas.csc.liv.ac.uk/Proceedings/aamas2025/pdfs/p2795.pdf) 使用 T5 卡牌/卡组语义、Transformer 表示、自博弈和辅助状态转移学习，测试包含未见卡牌的卡组。[官方仓库](https://github.com/WannianXia/GeneralizableHS) 可作为表示层和训练目标参考；这不是已证明当前标准职业水平的现成替代品。

我们可以先离线缓存卡牌文本向量，将运行时真实费用、身材、附魔和触发进度单独编码。文本表示不能代替规则引擎，也不必每步调用大型语言模型。

### 2.3 不必先实现最复杂的博弈算法

[Expert Iteration](https://arxiv.org/abs/1705.08439) 给出网络与搜索相互提升的路径，适合作为当前代码的过渡。其原始结果不是炉石，不应直接外推强度。

[IMPALA](https://proceedings.mlr.press/v80/espeholt18a.html) 可借鉴 actor/learner 分离和 V-trace 的策略滞后修正。初版可先做较容易核验的同步 recurrent PPO，分布式吞吐成为瓶颈后再引入异步架构。

[Reevaluating Policy Gradient Methods for Imperfect-Information Games](https://arxiv.org/abs/2502.08938) 的 ICLR 2026 工作表明，经过合适实现与评估的通用策略梯度方法值得作为强基线；不意味着 PPO 自动解决当前炉石，也不意味着不需要对手多样性。

[ReBeL](https://arxiv.org/abs/2007.13544) 提醒我们，隐藏信息下的搜索应围绕信息集/信念，而不能把采样的隐藏世界当作已经知道的真实世界。这里借鉴原则，不建议第一步在完整炉石上直接复刻全量 CFR/ReBeL。

## 3. 推荐的目标系统

```text
模拟器 / 真实公开日志
        ↓
统一 ObserverView（己方可见私有信息 + 公开状态/历史）
        + 对手候选分布及未知构筑质量
        ↓
逐实体编码 + 卡牌语义 + 公共历史记忆
        ↓
实体关系 Transformer
        ├─ policy：完整合法动作评分
        ├─ value：当前信息下的后续胜负
        ├─ action-Q：执行动作后的条件价值
        └─ 辅助头：可验证的状态转移、belief 等
        ↓
多数局面快速策略决策 / 重要局面额外搜索
        ↓
当前策略 + 历史策略 + 弱点针对策略的对手池
        ↓
新轨迹 → RL 更新 → 独立评测 → 合格后进入对手池
```

### 3.1 输入和模型

- 每张手牌、场上随从、武器、地标、英雄技能均独立成实体。身份、所属方、区域、位置、当前身材/费用、关键词、附魔、触发次数与计时器绑定在同一实体上。
- 独立编码双方任务、永久效果、光环、条件计数；明确公开/私有/未知字段，不能把模拟器真值直接全量传入策略。
- 公开历史编码先用小型 GRU/LSTM 或事件 Transformer；保留近期事件及长期汇总，避免硬截断丢掉已经完成的任务等永久信息。
- 己方牌库使用真正已知的组成/不确定性，不传真实未知牌序；对手输入职业、已展示卡、生成来源、留牌/抽牌历史及候选分布。未知构筑不能被强制压成某个已知完整套牌。
- 第一轮架构对照可用 d_model=256、6 层，再对照 384/512、8–12 层。它们是实验起点，不是已知最佳超参；实测参数量、NPU 吞吐和同预算对战后再扩大。
- 初期保留现有完整合法动作评分，使用源/目标实体的表示；动作分支特别大时再实验分层或自回归动作头，避免改变动作分解同时引入额外误差。
- 卡牌词表扩容采用版本化 ID→embedding 映射，保存完整 schema 与规则版本。未知卡仍有语义和动态特征；新 schema 不得静默兼容旧模型。旧结构与新结构不一致时，优先选择性迁移或蒸馏，不强行直接加载全部参数。

### 3.2 训练方式

第一阶段保留监督冷启动，但不能把教师标签当真理。已有 checkpoint 和成功对局仍有价值；新增输入只有在原始轨迹/快照包含相应字段时才能重新编码，不能从旧列式矩阵凭空补齐。

随后切入真正自博弈 RL，以终局胜负作为主目标。当前策略生成新局，与历史模型、不同风格基线和针对弱点的对手交锋，持续更新策略，而不是反复重放同一批静态标签。

建议先做 recurrent PPO 基线，保存 behavior log-prob、动作 mask、观察历史、player-to-act、终局/截断标志和策略版本。异步扩展时控制 actor 参数滞后，采用适当的 off-policy 修正。不能把已有任意离线教师行直接当作 on-policy PPO 数据。

搜索保留两种用途：生成高可信纠正标签，以及上线时对困难局面增加计算。为候选根动作分配覆盖预算，多隐藏状态/随机结果估值，并搜索到关键收益实际兑现。随机结果出来后重新决策，而不是缓存一整串盲执行动作。

特别注意：不能在每个采样的隐藏世界里选择不同的“当前不可观察分支动作”，再把收益平均并当作现实可实现策略；这会制造信息优势。应按决策者实际观察合并/分离分支。

value、Q、policy 应对齐同一观察和后续策略语义。终局结果与高预算 Q 标签都要带来源、样本数和不确定性；不应把启发式 Q 当成校准胜率。辅助状态转移先学可验证的确定性变化，随机结果用分布目标，不硬拟合一个不可预知的样本。

炉石同一玩家会连续执行多个动作：收益视角只在行动方发生变化时转换，不能机械地每走一步取负。未终局的时间/动作上限不能直接标成平局或失败。有限终局任务可先采用不按微动作折扣的胜负目标；这是一项新 RL 实现的检查要求，不是在声称当前代码存在该折扣错误。

### 3.3 数据扩展

127 套牌有 16129 个有序 matchup；本轮新增 2048 局不足以密集覆盖所有组合。历史数据另计，不能把 2048 当成项目全部经验；大量同局步骤和重复 epoch 也不能当作同等数量的独立对局。

数据扩展建议采用量级关卡：先约 1 万局验证新闭环，成功后 10 万局，再按学习曲线评估百万局级别。没有可信依据保证某个固定局数必然达到职业级；容量和样本需求应由学习曲线决定。

不要追求每两套牌完全均匀配对。按卡组族/战术类型、先后手、当前模型不确定性和薄弱 matchup 抽样；主流构筑、合法少量换卡变体、少量新颖组合共同组成训练分布。泛化留出按规范化卡表 hash 和卡组族划分，不能只靠名字。

至少保留三类数据：

1. 广覆盖完整自博弈轨迹，学习长期资源和胜利条件；
2. 学生实际访问局面的搜索纠正数据，处理分布漂移；
3. 大量程序化生成、独立留出的规则/战术组合题，用于训练辅助与评测，训练测试不能混用同一批根状态。

真实日志不是大规模学习的唯一来源，但适合验证模拟器、检测实战分布偏移，以及在授权条件下做高水平人类动作冷启动。人类动作也不是每个局面的唯一最优标签。

### 3.4 NPU 和模拟吞吐

NPU 负责批量网络推理/训练；当前 Python 规则执行、隐藏状态采样、克隆和树搜索主要在 CPU。不能靠增加 NPU 数量让不调用网络的启发式教师自动加速。

优先量化每秒有效环境步、成功对局/小时、克隆/合法动作/编码各自耗时、推理 batch 与排队 P95、NPU 利用率、actor 参数滞后。以这些数据决定 CPU worker 数和 NPU 数，不先“占满所有卡”。

规模化应采用多环境合批推理、持续模型驻留、紧凑观察张量、可裁剪的搜索副本、独立于训练轨迹的简洁日志。只对 profiler 证实的热点做 C++/Rust/Cython 等原生优化，不把整个引擎一次重写作为前置条件。

主要吞吐提升来自：多数采样动作由网络直接决策，少数局面搜索重分析。不再要求每个动作都支付 128 次 Python 搜索。910C/910B 上先验证新模型前向、反向、数值一致性和吞吐，再分配数据生成推理与 learner 资源。

## 4. 模拟器允许不完美，但要区分错误等级

遵守用户要求：已有失败/异常对局进入潜在问题库，成功教师对局继续可用，不等待标准全库达到零 bug。

但以下问题应成为训练前硬门槛：观察泄露、奖励正负/玩家视角错误、严重终局错误、系统性免费动作/重复动作循环、跨 clone 的状态串扰、schema 错位。它们会污染大量数据或让 agent 学会利用漏洞。

个别罕见卡交互可以记录版本和受影响轨迹，降权/隔离已确认污染部分，修复后再回放。不能把“没有抛异常”当成规则正确，也不能因为一处待查问题作废全部历史数据。

## 5. 验收必须分清三件事

| 验收对象 | 要回答的问题 | 不足以替代的指标 |
| --- | --- | --- |
| 规则/观察 | 是否在合法且同等信息条件下对局 | 只有程序没报错 |
| 策略改进 | 是否在固定预算下稳定击败旧模型与多样对手 | 教师 accuracy、训练 loss、单一 Brier |
| 职业水平 | 是否在当前版本、多卡组、合理时间与信息限制下对强人类竞争 | 模型自称高价值、少数精彩回放、历史旧版本论文 |

每轮保留旧模型纯策略、新模型纯策略、旧模型同预算搜索、新模型同预算搜索四组，区分网络提升与增加计算的提升。评测用独立种子，交换先后手，按配对种子计算统计区间；报告宏平均、可信 meta 加权平均、各卡组族以及最差分组表现。

阶段晋级可先要求配对胜率置信区间下界超过 50%，同时关键分组不显著倒退。最终还需对多个高水平玩家做盲测/固定规则比赛，报告足够样本和不确定性。可以事先冻结测试规模或采用有效的序贯检验，避免反复看成绩后挑有利时点停止。

“新卡组发现”是单独任务：强对局策略训练完成后，以合法构筑搜索/进化/策略梯度提出候选，再用独立环境对手分布验证。能适应未见套牌不等于自动会构筑最强套牌。

## 6. 推荐实施顺序与停止条件

| 阶段 | 主要交付 | 进入下一阶段条件 |
| --- | --- | --- |
| A：观察与数据契约 | ObserverView、逐实体 schema、公共历史、belief 接口、输入敏感性/不泄露测试 | 关键可见状态变化进入编码；隐藏真值变化不泄露 |
| B：神经自博弈最小闭环 | 实体模型、小规模 PPO/历史对手池、纯策略与搜索对照 | 新闭环在独立配对测试有可重复增益 |
| C：高质量重分析 | 神经教师入口、多随机样本、不确定性、独立战术生成器 | 搜索标签和策略提升可在未见根状态复现 |
